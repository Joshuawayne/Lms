# Agreed product requirements

School-term programs, Saturday Coding Club and holiday programs share one learner
profile and long-term history. Each enrolment retains its own attendance, activities,
assessments and reports. Delivery mode (in person or online) is separate from pathway.

The public website leads to authenticated administrator, teacher, learner and
parent/guardian portals. Assigned permissions determine accessible roles and records.
One account can hold multiple approved roles. A learner record can exist without
its own login account. Guardian relationships must be verified.

Administrators manage people, programs, classes, schedules, assignments of teachers,
content, assessment templates, imports, permissions and reports. Teachers create or
reuse content, take attendance, review submissions, assess practical work, record
observations, give feedback and approve publication. Learners access assigned work,
submit evidence, review feedback and work toward goals. Parents see the appropriate
released records of linked children.

The custom activity builder supports lessons/resources, worksheets, quizzes,
interactive video, branching choices, coding/Blockly activities, robotics/practical
projects and reflection. It needs templates, duplication, draft/preview/publish,
versioning and saved attempts. Adding an entirely new interaction needs development.
Compatibility with H5P packages is a separate future scope decision.

Spreadsheets can be either learning resources or structured database imports.
Imports use template, upload, validation, preview/correction, confirmation and a
summary. Duplicate/update rules and replay safety must be explicit.

Planned integrations: BigBlueButton for virtual classes, Gotenberg for document
conversion, Blockly for block coding and Python spreadsheet tools for imports/exports.
They are not integrated in this scaffold. Hosting and operations can have costs even
when the underlying software is open source.
