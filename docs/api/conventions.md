# API contracts

Prefix business resources with `/api/v1` and use clear plural resource names. Health
endpoints currently use `/api/v1/health/live` and `/api/v1/health/ready`. Schema
documentation is at `/api/openapi.json`, with Swagger UI at `/api/docs`.

Keep typed request/response schemas in FastAPI. Export a deterministic OpenAPI
snapshot into `contracts/api/v1/openapi.json`; generate frontend types from it.
Run `npm run contracts:generate` for intended changes and `npm run contracts:check`
to detect drift. Generated files should not be edited manually.

Errors use `application/problem+json` with title, status, detail, instance and request_id.
Field failures can include an errors list. Request IDs are generated by the server.
Responses must not include credentials, raw database errors or submitted passwords.

Future resource contracts must define bounded pagination and stable sorting,
allowed filters, actor/object authorization, retry-sensitive idempotency semantics,
concurrency conflicts, job statuses and observability. Authentication is not chosen
or implemented yet; the current client omits credentials. Idempotency helpers and
business-resource endpoints are reserved future work.
